# Agent Instructions

This repository documents and tracks only the Cloud SPE's assigned portion of
the wider Network Engineering SPE through versioned knowledge and a Beads work
graph. The Cloud SPE is one participating member; do not treat this repository
as the programme-wide source of truth, invent application behavior, or treat
working drafts as approved decisions.

## Navigate before changing

- Read [ARCHITECTURE.md](ARCHITECTURE.md) for boundaries and source precedence.
- Use [docs/index.md](docs/index.md) to locate the relevant spec, design,
  decision, or reference.
- Treat `docs/references/` as evidence and working material. Re-verify claims
  against the named repository and commit before relying on them as current.
- Keep work owned by other Network Engineering SPE participants out of this
  repository except where it is a named dependency or handoff for Cloud SPE work.
- Use Beads for all work state, dependencies, discoveries, and handoffs.

## Make changes verifiable

- Create or claim a bead before editing.
- Keep `AGENTS.md` navigational; put durable detail in the relevant document.
- Link decisions and specs rather than copying their text across files.
- Run `python3 scripts/check_docs.py` after documentation changes.
- Never add `Co-authored-by` trailers or equivalent co-author attribution to
  commits or pull requests.
- Do not commit, push, or sync Beads unless the user explicitly authorizes it.

## Beads Issue Tracker

Use Beads (`bd`) for durable task tracking in repositories that include it. Use the `beads` skill at `.agents/skills/beads/SKILL.md` (project install) or `~/.agents/skills/beads/SKILL.md` (global install) for Beads workflow guidance, then use the `bd` CLI for issue operations.

### Quick Reference

```bash
bd ready                # Find available work
bd show <id>            # View issue details
bd update <id> --claim  # Claim work
bd close <id>           # Complete work
bd prime                # Refresh Beads context
```

### Rules

- Use `bd` for all task tracking; do not create markdown TODO lists.
- Run `bd prime` when Beads context is missing or stale. Codex 0.129.0+ can load Beads context automatically through native hooks; use `/hooks` to inspect or toggle them.
- Keep persistent project memory in Beads via `bd remember`; do not create ad hoc memory files.

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/SYNC_CONCEPTS.md for details and anti-patterns.
