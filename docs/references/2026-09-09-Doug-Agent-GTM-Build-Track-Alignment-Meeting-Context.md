## Alignment objective

Reach a shared, explicit description of the boundary and interface between:

1. the Build Track's reusable, open, self-sovereign network access
   infrastructure;
2. Livepeer Inc's Livepeer Agent and Agent Product work;
3. Doug's proposed commercial GTM commitment; and
4. other demand bets that may consume the same public infrastructure without
   becoming Build Track demand-generation deliverables.

The discussion should make the Thursday announcement easier to state without
conflating public infrastructure delivery, commercial product delivery, and
demand generation.

## Required distinctions to preserve

- The Build Track enables demand but has no application-adoption, traffic, or
  demand-generation requirement.
- A commercial Agent offering may provide hosted operation, product choices,
  support, or fiat payment without making those commercial functions Cloud SPE
  deliverables.
- “Self-sovereign Agent” still requires an observable, agreed definition; it
  must not be inferred solely from a product name.
- Other demand bets should be able to use common public interfaces without the
  Build Track inventing their application behavior.
- A person or team being behind the current direction is a prompt to reverify
  assumptions, not evidence that any named repository or design is obsolete.
- Thursday's anticipated announcement remains pending evidence until its
  actual content and authority are recorded.
