Working with upstream

What we found, filed and fixed

livepeer/node #1 · fixed

The signer rejected orchestrators whose ticket recipient differs from their node address. Josh fixed it; it ships in node v1.0.2.

Python SDK #77 · in review

The SDK now reports each payment session it signs, so an app can see what every call cost, failed calls included.

livepeer/node #2 · worked around

Orchestrators with self-signed certificates: we pin their certificates in our stack instead of disabling checks.

SDK #74 · changed on review

Josh asked us not to read the signer’s private state; we match charges by the session’s ManifestID instead.

The build track depends on three upstream projects: the node remote signer, Clearinghouse Batteries and the Livepeer Python SDK. Where we hit a gap we filed it with evidence. Node issue 1 was fixed by Josh and is in v1.0.2. SDK PR 77 adds payment-session reporting and is in review; builder core pins our fork until it merges. Node issue 2 (self-signed certificates) was declined upstream, so the dev stack pins the orchestrators' certificates. And on SDK issue 74 Josh pushed back on our first design, which read the signer's private state to identify a payment; we switched to the session's ManifestID, which is what PR 77 now does. The signer, Batteries and engine all deploy to Railway.
